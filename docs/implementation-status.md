### Event / payout integrity update — 2026-11-04

- Financial event envelopes now reject unknown top-level fields under schema v1 rather than silently accepting unversioned extensions.
- Canonical-engine-shaped `OUTCOME_COMMITTED` events carry base, feature and total milli-payouts as a complete triplet. Replay checks the feature total against resolved feature events and checks total = base + feature.
- GameEngine feature traces include the actual round-payout increment for each Free Spin. Wallet event persistence uses that awarded increment, not the unadjusted raw win.
- Current MathPort outputs are type-checked without `int()`/`bool()` coercion. BASE awards are enforced as 10 for 3 Scatter and 12 for 4; 5 requires the blocked embedded EPIC payload; 6+ and nonzero Free Spins retriggers fail closed.
- The historical Draft-005 Divine Jackpot execution path is disabled. The Math evaluator never triggers it, and GameEngine rejects any MathPort attempting to trigger a jackpot, consistent with Stake Engine's published stateless-game restriction. Ordinary in-round payout cap accounting remains testable; it does not establish 50,000× reachability.
- These changes strengthen local deterministic replay and reconciliation; they do not activate canonical Math, real-money rounds, Provider connectivity, or public release.

Local recovery tests cover debit interruption, committed-outcome settlement recovery, lost-credit and lost-refund responses, separate-process termination after debit/outcome/credit/refund, stale fencing token, expired-token idempotent replay rejection and refund/commit race. New demo tests cover session idempotency, concurrent duplicate requests, ordered fixture events and proof that demo spins do not change wallet balance or journal. Service-generated outcomes are now checked at the ledger boundary for mode and milli-bet-to-minor-unit payout consistency. This does not establish multi-host distributed guarantees.

The `ganesha.game.presentation` contract supports `TEST_FIXTURE_ONLY` and explicitly non-financial `NON_FINANCIAL_SIMULATION` authorities including `DRAFT_ONLY_NOT_RELEASE_EVIDENCE`; this does not confer canonical or Provider authority. `GameFixtureSessionStore` connects the real GameEngine, deterministic fixture adapter, event reducer, loopback HTTP API and Frontend renderer. A separate local RoundService test now drives the actual DraftMathPort through Exact-3, ten Free Spins, Wild Expansion, Presentation replay and SQLite Wallet settlement, including the exact Draft maximum path. It does not connect the non-financial GameRuntime database to the Wallet or authorize canonical outcomes. MAGIC BUY/EPIC BUY remain excluded. See `docs/game-presentation-contract-v1.md`.

The earlier `artifacts/BROWSER_SMOKE_20261104.json` is historical and covers only the legacy scripted Demo. The current GameEngine fixture browser run is recorded separately in `artifacts/BROWSER_SMOKE_20261104_ENGINE_FIXTURE.json`. Even a successful fixture browser run does not validate canonical Math, random gameplay, physical iOS/Safari, Stake iframe, Wallet, or Provider.

## Important scope boundary
The local SQLite/HMAC/HTTP code is a reference architecture. It is not a production payment system, not connected to Stake, and not evidence of Provider approval. The frontend currently disables wagering controls.
