## Security verification hardening — 2026-11-07

`src/ganesha/security/verification.py` now validates the untrusted HMAC signature wire value before calling `hmac.compare_digest` indirectly through the signing primitive. Only a 64-character lowercase hexadecimal SHA-256 HMAC string is accepted. Non-string values (including bytes, integers, mappings and arbitrary objects), wrong lengths, non-hex values, and payloads that cannot be canonically serialized now fail closed as `False` rather than leaking `TypeError`/`ValueError` into the request handler. Invalid signatures do not consume the otherwise valid nonce. Regression coverage is in `tests/test_security_request_envelope_fail_closed_20261107.py` (5 cases).

This is local input-validation evidence only. It does not establish Provider-side key custody, production request signing, distributed nonce storage, or live RGS authorization.
